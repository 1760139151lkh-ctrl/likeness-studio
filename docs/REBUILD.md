# 哈基秀 · 重构诊断、方案与验收记录

> 对应任务书「`likeness-studio` 艺术头像与实时滤镜新版本」。本文记录：旧版问题诊断 → 重构设计 → 视觉资产清单 → 验收结果。

---

## 1. 旧版诊断（基于 `studio` 分支 b372fa4 通读）

### 1.1 架构：四个产品挤在一个壳里
| 问题 | 证据 |
|---|---|
| 一个 App 里叠了 **4 套互不相干的产品**：风格肖像（portrait/）、发型妆容试戴 Lookbook + 镜子（looks/）、和工作室聊天的 Desk（ui/desk）、房间/天气主题系统（room/） | `web/js/main.js` 先把 Desk 铺在最底层，Lookbook 是另一个「地方」，引导页又是另一个覆盖层 |
| 单文件过大、难以维护 | `looks/mirror.js` 141 KB、`studio/painter.js` 131 KB、`room/maker.js` 100 KB、`looks/book.js` 64 KB；前端合计约 1.65 万行 |
| 三套导航机制并存 | `core/nav.js` 的 step 栈 + Lookbook 用 `is-away` class + `MutationObserver` 监听跳 Desk + 返回按钮靠运行时 `prepend` 注入（`lb-home`、`desk__home`） |
| 运行时资源冗余 | `vendor/` 24.7 MB，其中 6 MB `magic_touch.tflite`、0.8 MB 发型分割模型只服务于已下线的功能 |

### 1.2 延迟：每一步都在多花时间
| 环节 | 旧做法 | 代价 |
|---|---|---|
| 默认引擎 | Codex CLI（`auto` 只会选 Codex/模拟器，直连 API 永远不会被自动选中） | 一张肖像约 **60 秒** |
| 上传 | 点「开始画」时才上传，最长边 1600、JPEG 0.92 | 等待叠加在生成之前 |
| 服务端存图 | 上传图与成片都转成 **PNG** 存盘 | 单张 1–3 MB，手机下载慢 |
| 发给 OpenAI | 再次把输入转码成 PNG 发送 | 多 MB 的请求体，上行变慢 |
| 并发 | `workers = 2` | 两人同时就排队 |
| 等待反馈 | 本机先画一张「Sketch」草图占位，然后靠一句英文阶段名 | 黑盒感 |

### 1.3 布局拥挤与导航死胡同
- Lookbook 的「ask bar」一条输入框里塞了 `+` 菜单、token、相机、发送、Them/You 切换——正是任务书说的「多个按钮挤在底部一个小输入框」。
- 创作页顶栏同时有返回、步骤条、撤销、重做、关闭五个控件；结果页 6 个动作平铺。
- Desk 只能通过在 Lookbook 输入「不是妆容的词」才能进入；Lookbook 的返回按钮是注入的，部分状态下没有。

### 1.4 视觉：缺乏个性与「无效样例」
- 默认「Salon」深色房间，整体黑白灰；风格名换了，界面情绪没换。
- `web/examples/` 里每个人 7 张「刘海左/右/侧脸、唇色、眉形」局部图（共 56 张）——即任务书里「七张莫名其妙的人脸局部图」，与「艺术头像」这一卖点无关。
- 示例人物以欧美面孔为主，与新马/亚太 TikTok 年轻用户脱节。

### 1.5 数据：没有账号
- 数据只在浏览器 IndexedDB；服务器端按「配对设备」隔离，没有账号、没有跨设备同步、没有访客 → 登录的归属。

## 2. 重构设计

### 2.1 信息架构（只有两个根页面）
```
实时变身 (#/live) ⇄ 上传精修 (#/studio)        ← 两个平级核心入口，底部模式切换，互相一键直达
   │                    │
   ├─ 结果页 (#/result/:id)   ├─ 作品库 (#/gallery) ─ 作品详情 (#/work/:id)
   └─ 我的 (#/me)            └─ 我的 (#/me)
所有子页面左上角固定「返回」；所有抽屉右上角固定「关闭」；抽屉也占一格历史，手机返回手势先关抽屉。
地址即状态：刷新后回到原页面；直接打开详情页时自动在下面垫一个根页面，「返回」永远有地方回。
```

### 2.2 模式 A · 实时变身
- 9:16 全屏取景器（桌面端居中手机框）。顶部：作品库 · 分类胶囊 · 我的；右侧：翻转/强度/对比/精修；底部：真图圆形风格轮播 + 居中快门 + 模式切换。
- **本机实时渲染**（`web/js/live/`）：单 pass WebGL 着色器按风格参数做调色、赛璐璐色阶、描边、网点、像素化、**跟脸走的大头/大眼变形**、保边磨皮、霓虹轮廓光、柔光溢散、扫描线、颗粒；MediaPipe 478 点人脸追踪驱动 **生成的透明贴纸**（皇冠、哥特冠、小龙头套、猫耳、狗耳、机器猫耳、黏土毛线帽、英雄头冠）和每个风格的 AR 画框/HUD/粒子。
- **按下快门 = 乐观交接**：立刻带着这一帧跳到结果页（零等待），压缩/存档/上传/发起生成在后台进行；结果页上即时预览 → 过程图 → 高精成片平滑切换。
- 结果页：按住看原图；底部风格条点一下 **不用重拍直接换风格**；微调细节（带着照片和风格进上传精修的「细节」页）/ 保存相册 / 去发 TikTok / 重新拍。
- 摄像头权限被拒或无摄像头：取景器里直接说明原因 + 一键去「上传精修」。

### 2.3 模式 B · 上传精修
- 一次上传，无限换装：同一张照片的所有版本排成一排；风格 | 微调 | 细节 三个标签收纳进阶项。
- 微调：**风格强度 / 保留像貌 / 细节丰富度 / 美颜微调** 四个滑块（各 4 档映射到精确的 Prompt 措辞），画幅（头像 1:1 / 竖版 2:3），画质（极速/高清/超清）。
- 细节：**配饰 / 光效 / 背景氛围 / 画框装饰** 每组 2 个选项（背景、画框组内互斥）+「补一句」自由描述（卡片固定在屏幕上方，软键盘挡不住）。
- 生成前：风格卡片 + 一句话卖点 + 本机识别的构图小贴士（亮度、能否找到正脸、脸是否太小）。生成中：三阶段进度 + 预计剩余 + 随时取消。生成后：前后对比自动扫一遍 + 「已自动存入你的专属作品库」+ 底部主按钮位置换成「微调细节 / 换个风格 / 保存相册 / 去发 TikTok」。
- 每个版本自动记入**创作轨迹**（相对上一版改了什么：换风格、滑块从几到几、加/减了哪个细节、补了哪句话），在作品详情里完整可见。

### 2.4 「一风格一世界」主题系统
- 17 个预设各有一套主题 token（背景渐变、表面色、文字色、主/辅强调色、光晕、**画框形状**、**展示字体气质**、**装饰语言**）+ 一张生成的专属氛围背景图。
- 颜色变量用 `@property` 注册为可插值属性，切风格是 0.5 秒柔和过渡，不闪不跳；首屏用上次的主题预先上色，刷新不闪默认色。
- 画框语言同时作用于风格卡与成片框：公主拱形+玫瑰金、哥特尖拱+银边、特摄切角能量框、贴纸白边、漫画粗描边+错位阴影、黏土糖果厚边、机甲细线发光、盲盒包装窗、像素阶梯边、CCD 橙色日期戳、胶片白边相纸、霓虹双色灯管。

### 2.6 低延迟
| 环节 | 新做法 |
|---|---|
| 引擎 | `auto` 在配置了 Key 时直接选 **GPT Image API**；默认画质「高清」= `gpt-image-2.6-flare` medium，实测 **约 10 秒/张**（「极速」≈ 7–8 秒，「超清」= sunburst high ≈ 30 秒） |
| 上传 | 手机端先压缩（最长边 1280、JPEG 0.88）；**选好照片立刻后台预上传**，点「一键变身」时图早已在服务器 |
| 传输 | 服务端存 JPEG（成片 q92）；发给 OpenAI 直接用 JPEG，不再转 PNG |
| 并发 | `workers` 4；同一个生成 id 重发（断网重试）返回同一个任务，不会重复生成 |
| 前端 | 静态资源带版本号永久缓存 + Service Worker；骨架/即时预览/过程图三级占位；SSE 推送，代理吞流时自动降级轮询 |

### 2.7 账号与私有空间（`likeness/accounts.py`）
- 每个访客第一次打开就拥有一个**访客账号**和独立私有空间（上传、成片、记录互相隔离：别人拿到链接也取不到你的图和任务）。
- **注册 = 访客账号原地升级**，所有作品原封不动；**登录已有账号 = 访客的记录与图片整体并入**（新者为准），访客空间随后回收。
- 记录同步：作品 / 原图 / 收藏风格 / 草稿 / 偏好，本机 IndexedDB 先落地、再按**服务器游标**增量同步（不依赖设备时钟），最后写入者胜。清空浏览器数据后登录，作品从私有空间拉回。
- 密码 scrypt 加盐；会话 token 只存哈希；连续输错 8 次限流 5 分钟。

## 5. 第二轮打磨（2026-11-20 下午）

**角色还原**（后来已换成原创设计，见 §6.6）：光之巨人 → 经典奥特曼（银红战衣、彩色计时器、头冠鳍，细节可选「斯派修姆光线手势」「红灯警报」「怪兽城市」「M78 星云」）；蓝胖子 → 哆啦A梦头套（红鼻子、胡须、铃铛、四次元口袋，细节可选「竹蜻蜓」「铜锣烧」「任意门」「大雄房间」）；奶龙恶搞 → 还原奶龙的大嘴贱笑。实时镜头信物：奥特曼头冠、会转的竹蜻蜓 + 红鼻子胡须、奶龙小角头箍。

**样张铺满**：每个风格都在 6 位人物身上各变身一次（21 × 6 = 126 张样张；动漫主角与 3D动画脸加强风格化后整组重画，默认「保留像貌」对二次元类调到 62–70，让画风真正立起来），新增「样张」抽屉：左右拖看变身前后、换人看、一键「拍同款」或「用这个」。入口：实时变身的风格名、上传精修画面左上角的风格卡、作品详情的「拍同款」。

**沉浸感**：停在新世界上弹出标题卡（信物 + 风格名 + 口号，从快门处晕开）；出片时一道光从左扫到右完成蜕变，同时这个世界的信物四散飞出，手机轻震；全部尊重「减少动态效果」。

**第二轮资产**：新生成 98 张（84 张样张、6 张背景、8 个贴纸）+ 22 张二次元加强版与对比备选；点名在世导演画风的备选有 1/3 被内容审核拦截，因此正式 Prompt 不点名导演，只点名作品（这些全部通过）。全站现有：6 位示例人物、126 张样张、22 张氛围背景、19 个透明贴纸、1 个图标（`web/img/`，约 23 MB，按需加载：轮播用 192px 头像缩略、卡片用 360px、只有样张抽屉和首屏引导加载大图）。

**第二轮修掉的 bug**（都在验收中发现）：点圆头像平滑滚动时途经的风格被逐个选中、主题一路闪过（现在途经的不算选中）；出片完成通知发了两次导致揭晓动画和粒子重复（现在只宣布一次）；看着成片换了风格后，底部仍是「下一步」而不是「一键变身」；样张抽屉的对比图和竖版作品详情图在 grid/flex 里塌成 0 宽；出片后画面左上的风格卡被隐藏、无法打开样张。

## 6. 第三轮：上传精修工作台重构，旧功能全部回归（2026-11-21）

动手前先把本地版本原样推到 `hajixiu` 分支（`b0cc274`）做备份。这一轮的原则：先把核心流程做顺；旧版里好用的功能一个不丢，收进面板和二级层里；清单只是底线。

### 6.1 这一轮解决的痛点
| 痛点 | 做法 |
|---|---|
| 键盘把页面挤扁、顶走 | 打字时舞台高度锁住（`--app-h`），键盘只是盖住底部；需要打字的那一条（对话输入、补一句）带 `.kb-lift`，刚好贴住键盘上沿；视口 `interactive-widget=resizes-visual`（`core/keyboard.js`） |
| 控件挤、容易点错 | 照片下面一排五个工具：风格 · 微调 · 细节 · 部位 · 对话。面板统一高度（`--panel-h`），切工具零跳动；面板打开时主按钮、模式切换、版本条让位，照片平滑缩到面板上方 |
| 部位精修挤在一条小栏里 | 「部位」一整块面板：本机 MediaPipe 认脸，点脸上哪里就选中哪个部位；形状类（刘海、发型、眉形…）在照片上描虚线并标出选了什么；颜色类（发色、唇妆、腮红）当场逐像素染色预览，发色分全染 / 挑染 / 渐变 / 内层；「圈选」用手指涂出任意一块，可撤一笔、清空；可以附参考图 |
| 没有撤回 | 上传精修的每一步（换风格、调滑块、选细节、选部位、出图）都能撤回 / 恢复，刷新后历史还在；结果页能撤回到上一版再恢复；电脑上 Ctrl/⌘+Z、Ctrl/⌘+Shift+Z，Esc 收面板 |
| 等待时心里没底 | 三段进度（读图 · 绘制 · 收尾）+ 预计秒数 + 中途预览图，可取消，失败可重试；多张一起出时显示「已出 2/3 张」 |

| 主题色藏起来、界面发灰 | 工具、主按钮、选中态、部位高亮都用当前世界的强调色 |

### 6.3 服务器
- `POST /api/turns` 新字段：`say`（这一步在对话里怎么说）、`pins`（每个部位一张遮罩和一句说明）、`taste`（我的口味）、`room.voice`（回复的口吻）。

### 6.5 自测中发现并修掉的问题
- 刷新得太快（300ms 内）会丢最后一步草稿：草稿同时写一份到 localStorage，页面收起或关闭时立刻落盘，启动时补回。
- 结果页换过版本后「恢复」失效（恢复记录跟着页面一起重建丢了）。
- 关抽屉和跳页面同时发生时，跳转被返回动作吞掉：改成排队执行；直接改地址时抽屉也会关掉。
- 启动时撤回历史比按钮先恢复，导致白屏。
- 贴纸 404（资产清单过期）：重新生成清单。
- MediaPipe 的普通日志被当成错误打到控制台：静音。
- 没有 GPU 的手机上实时镜头卡、点了要等：认脸频率和画面分辨率按设备自动调，认脸放到单独的任务里，点按先响应。
- 发色预览：黑发染浅色会发紫，强调色高光也把颜色带偏：改成逐像素染色，保留发丝明暗。
- 部位精修把头上的皇冠一起改没了：遮罩里只改说明要改的东西。
- 「用时 X 秒」只算了绘制阶段：改为从按下到出图。
- 对话里点正在看的那版缩略图没反应：改为收起面板看大图；结果页点当前风格没反应：改为打开它的样张。
- **同步会吞掉刚改的东西**：同步进行中的那一两秒里改了偏好、草稿、收藏或自创风格，服务器回来的旧版本会把它盖掉，推送完还会把改动前的那份标成「已同步」，刷新后就回去了。现在每条记录记着本机最后一次写下的时间，旧的盖不掉新的。
- iPhone（WebKit）上的软键盘：浏览器为了露出输入框会把整个页面往上滚、把面板正文滚过头，顶栏被推出屏幕、输入框被面板裁掉。现在页面本身永远滚回原位，输入框保证整个露在面板里、贴着键盘上沿。
- 抽屉打开 60–120ms 后会把光标挪到关闭按钮 / 第一个输入框，如果你已经点进了抽屉里的输入框，刚打的字会落空（我的口味、注册都可能丢字）。现在已经在抽屉里打字时不再抢焦点。
- Safari 上刷新时，下到一半的认脸模型被取消会在控制台留一条错误：页面在走的时候不再报。`interactive-widget` 只写给认识它的浏览器（Safari 不认识，会报警告）。
